<objective>
Fix the latent bug in DNAInference.generate_dataset (dnallm/inference/inference.py:439-458): a path-shaped string that fails os.path.isfile() silently falls into `sequences = [seq_or_path]`, producing a one-row dataset with only a 'sequence' column. This was the root cause of census 05-06's `['sequence']`-only dataset in the benchmark flow (recorded in tests/examples/test_notebook_execution.py:98: the benchmark notebook's `path: ../inference/test.csv` resolved against the wrong cwd, missed isfile(), and the whole path string became one "sequence", crashing downstream — now with a descriptive ValueError after quick task 261010-uz0, but still silently wrong at the source).

Purpose: make the str-handling contract explicit — the method's own docstring already promises `ValueError: If input is neither a file path nor a list of sequences`, and the silent str-fallback violates that contract. A missing data file must fail loudly at the point of misuse, not corrupt the dataset shape.
Output: two commits on dev (red-first regression tests, then the fix), targeted inference lane green, ruff clean on both touched files, no attribution trailers.
</objective>
