Product code stays untouched — hard guardrail; the repr style is the convention, and the message is not the bug.
2. Failure mechanics: repr doubles backslashes. On Windows the absolute tmp path (C:\Users\RUNNER~1\...\x.tsv) is embedded in doubled-backslash form, so the current assertion `assert missing in str(excinfo.value)` (tests/inference/test_inference.py:235) — which checks the raw single-backslash form — never matches; the subTest reports SUBFAILED. On Linux tmp paths carry no backslash and repr adds only surrounding quotes, so the raw substring is present — which is why only the Windows job failed on commit 67953b6.
3. Local red reproduction (verified live on dev): the raw string literal r"C:\no_such_dir\x.tsv" is path-like on Linux too (the backslash counts as a separator in _is_path_like_string) and os.path.isfile is False for it, so generate_dataset raises with the doubled-backslash repr message; a raw-substring assertion on it fails on Linux with the same mismatch shape as the Windows CI log. Genuine red-first needs no Windows host.
4. The exact predicate: an f-string !r conversion is exactly repr(x) for str, so `assert repr(missing) in str(excinfo.value)` holds on every platform for every shape in the loop — bare filename (repr adds only quotes), POSIX tmp path (no backslash to double), and Windows-style literal (both sides carry the doubled form).
5.
