## Objective

Land the packaging half of Phase 25's atomic first act: declare the `tui` extra (`textual>=8.2,<9`, `platformdirs>=3.6,<5`), ride it on every pytest CI leg through `test = ["dnallm[tui]", ...]`, add it to `all`, and delete the deprecated one-cycle `base` alias (PKG-01) in the same change — with the extras-guard contract rewritten to assert the new surface. This plan contains no TUI code and no panel; it makes `import textual` work in the dev venv and on every CI leg before anything renders.

Purpose: TUI-01's install wiring and PKG-01's pre-committed removal share the same install lines, so they land in one sequencing window with one release-note moment.

Output: updated `pyproject.toml` extras table, rewritten `tests/test_extras_guard.py` contract, three docs files brought in line with the removal.

## Locked in-plan decisions

- **`tui` is NOT added to `full`.** `full = ["dnallm[dev,test,notebook,mcp]", "isort>=6.0.1"]` stays byte-identical: `dev` composes `dnallm[test,notebook]`, `test` gains `dnallm[tui]`, so `full` already reaches textual transitively; adding it directly would fail `test_full_extra_members_preserved` (exact-set, both directions).
- Resulting lines: `test = ["dnallm[tui]", "pytest>=8.4", ...]`; `full` unchanged; `all = ["dnallm[full,dev,test,notebook,docs,ui,mcp,fla,tui]"]`.
- **PKG-01's literal target is `base`, not `full`.** REQUIREMENTS.md TUI/PKG wording says the "one-cycle `full` extras alias" is removed; the actual deprecated alias in `pyproject.toml` is `base = ["dnallm[full]"]`, marked "Remove in v1.4". `full` is the real extra and stays.
- **Dependency legitimacy:** RESEARCH's audit marks both packages `[SUS]` only because the seam cannot read PyPI download stats and platformdirs' newest release is fresh. Both resolve to canonical upstream repos (`github.com/Textualize/textual`, `github.com/tox-dev/platformdirs`), carry no install scripts, and are pinned by owner-authored ranges in REQUIREMENTS TUI-01. `workflow.human_verify_mode` is `end-of-phase`, so there is no mid-phase blocking checkpoint; the approval is recorded at the phase-end human check in 25-10, with the PyPI/upstream identity evidence inline in the threat register.
