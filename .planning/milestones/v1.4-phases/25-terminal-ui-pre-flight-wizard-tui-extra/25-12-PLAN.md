## Objective

Close the three copy gaps the phase's UAT reported under Test 4 (D-10), without touching the core, any behaviour, or any gate: every task-type string must define all eight allowed values in plain language from one shared source, the LoRA target-modules hint must say what its example names are and where valid names come from, and error sentences that send the reader to another screen must name that screen.

Purpose: 25-11 scoped its task-type gloss to three examples (binary/multiclass/token) and the copy implemented that contract verbatim, so the strings pass their own tests while leaving a biologist whose model needs embedding, mask, generation, multilabel or regression to guess. The vocabulary also lived as four independent prose literals, so no single edit could keep them consistent. This plan replaces the four literals with one composed source and applies the UAT truth literally: all eight, everywhere a task type is offered.

Output: one shared `TASK_TYPE_GLOSSES` mapping and its composed sentences in `dnallm/tui/copy.py`, a static eight-value legend under the suitability task input, a provenance-carrying LoRA hint, anchored navigation sentences, and tests that pin completeness and prove the copy cannot drift from the core's accepted values.

## Locked in-plan decisions

- **One copy-side source; the core is not changed.** `TASK_TYPE_GLOSSES` is an ordered `dict[str, str]` in `dnallm/tui/copy.py` (the copy layer is the presentation contract). A drift test reads the live `TaskConfig` field pattern from `TaskConfig.model_json_schema()["properties"]["task_type"]["pattern"]` and asserts the copy's eight equal the core's canonical values (every allowed spelling that does not end in `classification`; the four long-form aliases are exactly the `classification` spellings listed in `dnallm/configuration/configs.py:118-130`). Exporting a constant from the core was considered and rejected: it changes validation-adjacent core code for a copy concern and needs its own core test, while the drift test delivers the same guarantee at the boundary.
- **The truth is applied literally to all four sites.** Each task-type sentence carries all eight values and all eight glosses, composed from the mapping. 25-11's three-example scope is exactly what failed; no site is allowed to carry a partial list, even the two error sentences.
- **The suitability legend is static, the placeholder is a pointer.** An `Input` placeholder is one clipped line and disappears on the first keystroke — the debug note's structural complaint. `SUITABILITY_TASK_PROMPT` becomes a short pointer and `SUITABILITY_TASK_LEGEND` (ten lines: a header, one line per value, a closing line) renders as a `Static` directly under the input inside `#suitability-body`. The same legend also explains the raw task-type words in the listing table below it, without altering those verbatim values.
- **The generic list error drops the LoRA-only example.** `not_a_list` serves every list field (Output names is read-only; LoRA target modules has its own hint directly above it), so the shared template becomes "{label} needs a list separated by commas." with no example. The field-specific provenance lives in the target-modules hint.
- **The LoRA hint is 226 characters because that is the longest sentence that fits the 80x24 config viewport.** The pre-revision wording (462 characters) renders 16 rows of 32 columns inside `#config-form`, which is 9 rows tall at 80x24, so `test_the_hinted_form_stays_legible_at_80x24`'s `form.region.contains_region(hint.region)` can never hold — a widget taller than its viewport cannot be scrolled into view. Measured on the real Pilot app: 226 characters render 8 rows and are contained; 228 render 9 and are not. The chosen sentence keeps the three facts the UAT gap asks for (what query and value are; empty means the built-in choice, qualified to a listed family because `_resolve_peft_preset` raises for an unmatched one; where the per-family names live) and drops only the illustrative "decide which DNA letters to read" clause. Moving provenance into a second widget was considered and rejected: the UAT truth is about the hint itself, and a new widget would put `dnallm/tui/screens/config.py` and its CSS in play for no contract gain. A `<= 226` source pin in `test_copy.py` records the budget; the existing 80x24 containment assertion remains the rendered proof and is not modified.
- **The suitability legend costs ten rows, so the two 100x40 click tests scroll before clicking.** Measured with the legend mounted at (100,40): `#suitability-use` sits at y=38-40, below the 37-row body's bottom edge, so `pilot.click("#suitability-use")` raises `textual.pilot.OutOfBounds`. The fix is `scroll_to_widget(..., animate=False)` plus `await pilot.pause()` in `tests/tui/test_screens.py::test_selecting_a_listing_row_records_it_in_wizard_state` and `tests/tui/test_app.py::test_the_whole_wizard_walks_to_a_downloaded_model_summary`. The legend is never shrunk and no assertion is weakened to make the click land.
- **Navigation sentences are composed, not retyped.** The destination name in each sentence is the constant the destination screen renders (`SUITABILITY_PANEL_TITLE`, `USE_MODEL_ACTION`, `ENTRY_PANEL_TITLE`), so renaming a screen renames the sentence.
- **No behaviour change.** Copy strings plus one rendered `Static` plus one CSS rule; the save gate, the kept-as-is block, the read-only facts, the seam table and every core module are untouched.
