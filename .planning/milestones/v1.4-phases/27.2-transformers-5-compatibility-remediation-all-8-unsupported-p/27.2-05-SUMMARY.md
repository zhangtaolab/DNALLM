**The shared support vocabulary now reaches both live model menus: every preflight row carries `support`, the TUI suitability table shows it as a sixth text column, and every MCP `get_all_available_models` row and text line ends with the same word — additively, with the availability column and callability ladder untouched**

## Accomplishments

- `ListingEntry` gained one additive frozen field, `support: str` (default `"untested"`, non-empty). `_build_listing` populates it from `dnallm.models.support.support_word` for every row — the same function the docs story uses — so a finetuned entry inherits its base model's word through the shared chain and nothing is re-derived per surface.
- The TUI suitability table now declares six columns ending in `Support`; `_listing_cells` appends `entry.support` as the last cell (index 5). `_AVAILABILITY_COLUMN` is still 4, so the refresh writer, the on-demand update, and the per-row probe keep touching only the availability cell.
- MCP `get_all_available_models` rows gain `support=support_word(entry)` inside the existing `all_entries` loop, and each rendered line appends that same word as a fifth `|`-separated segment after the unchanged callability ladder. Tool names, parameters, envelope keys, counts, overlay matching, and client signatures are untouched.
- Cross-surface wording is equal by construction and pinned by tests on all three surfaces (no new mapping table anywhere; no raw `tf_compat_status` enum reaches a listing).

## Decisions Made

- `support` is additive with an `"untested"` default rather than required: every direct construction in the existing suite and any external consumer keeps validating, and the default is the honest word for "no verdict".
- The TUI column trails Availability specifically so `_AVAILABILITY_COLUMN` can stay 4 — the refresh writers are index-pinned, and renumbering them would have been the riskiest possible edit for a text-only addition.
- MCP: the support word goes after the status ladder (not before) so the ladder's precedence remains the fourth segment and existing consumers parsing that position keep working; the new segment is purely additive at the tail.
- Neither surface builds its own word table: the TUI renders the core's field, the MCP row calls the same function — the plan's prohibition against duplicate mappings is satisfied structurally, not by discipline.
