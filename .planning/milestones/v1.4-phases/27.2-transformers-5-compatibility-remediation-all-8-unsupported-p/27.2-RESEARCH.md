## Summary

Every one of the four code fixes was prototyped and measured green in this session against the real cached checkpoints on the project venv (transformers 5.17.0, torch 2.11.0+cu130, CUDA). Three of them are one-operator changes; the fourth (GENA-LM) is a one-line buffer reset whose **value, shape and root cause in the source todo are wrong** and must be corrected before planning. Two structural facts change the shape of the plan more than any individual fix:

1. **The census instrument does not run dnallm's loader.** `scripts/census_compat.py`'s load probe does `import dnallm` (to arm the rungs) and then loads through **plain `transformers.Auto*` classes** (`build_load_program`, `scripts/census_compat.py:887-985`). A fix living only in `dnallm/models/special/dnabert2.py` is therefore **invisible to the census**, so DNABERT-2 could never earn its D-02 green flip. This is a direct conflict between D-05 (fix in the handler) and D-02 (flip only on a census-measured probe) that the planner must resolve explicitly.
2. **A green re-probe does not automatically become `shim-required-tf5`.** `compat_verdict()` maps a green load to `verified-tf5` unless `SHIM_RESTORED_LOADS` names a rung (`scripts/census_compat.py:1315-1317`, consumed at `:1371`). The four repaired models must be added there (and to the independent mirror in `tests/models/test_model_info_registry.py:480`) or the registry will publish a false "works as-is" claim — violating D-03.

**Primary recommendation:** keep the todo's Plan A/B/C three-plan split, but order the work as **instrument → fixes → re-probe → registry → docs → listings**, and make the DNABERT-2 census-visibility decision (and the GENA-LM wording correction) explicit plan steps rather than assumed details.

### Anti-Patterns to Avoid

- **Claiming a rung for a fix that lives in a handler.** `test_shim_required_evidence_names_rung` (`tests/models/test_model_info_registry.py:407-423`) greps `_patch_[a-z0-9_]+` out of the evidence string and asserts `def <rung>(` exists **in `dnallm/utils/transformers_compat.py`**. A DNABERT-2 evidence naming `_install_dnabert2_tf5_shims` fails unless that test is extended.
- **Hand-editing `docs/user_guide/model_compatibility.md`.** It is generator output; the drift gate fails on any mismatch with a fresh `--emit-docs`.
- **Flipping a disposition before the probe.** D-02; the artifact's stale `skip` dispositions are dropped automatically on a verdict change (`merge_records`, `scripts/census_compat.py:1162-1196`), which is exactly why `SHIM_RESTORED_LOADS` becomes load-bearing.

## Per-Fix Findings (the eight items)

### Fix 1 — GENERanno (R4, D-04): ROPE `'default'` alias

**Current failure (reproduced):** the remote `GenerannoRotaryEmbedding.__init__` sets `self.rope_type = "default"` when `config.rope_scaling is None` and then indexes the table:

```
self.rope_init_fn = ROPE_INIT_FUNCTIONS[self.rope_type]
```
`[VERIFIED: ~/.cache/huggingface/modules/transformers_modules/GENERanno_.../modeling_generanno.py:126 — quote verbatim]`

with `from transformers.modeling_rope_utils import ROPE_INIT_FUNCTIONS` at line 42 of the same file. Under 5.17 the table has no `'default'` key:

```
['dynamic', 'linear', 'llama3', 'longrope', 'proportional', 'yarn']
```
`[VERIFIED: live probe, this session — `sorted(ROPE_INIT_FUNCTIONS.keys())` on transformers 5.17.0]`

**Why an alias needs a vendored function, not a pointer:** transformers 5.17 removed `_compute_default_rope_parameters` outright (`hasattr(module, '_compute_default_rope_parameters')` → `False`), and 5.x stock models compute default RoPE in a per-model staticmethod that reads `config.rope_parameters["rope_theta"]`. A stock 5.x config **has no `rope_theta` attribute** (`LlamaConfig().rope_theta` raises; only `rope_parameters` exists), while the remote GENERanno config has `rope_theta` and no `rope_parameters`. So the registered default initializer must be the **4.x-semantics** implementation.
`[VERIFIED: live probes this session — table keys, `_compute_default_rope_parameters` absence, and the `LlamaConfig` attribute shape]`

**Minimal fix shape (verified):**

```python
# shape verified live: registering this alias is the only change needed
def _compute_default_rope_parameters(config, device=None, seq_len=None, **kwargs):
    base = config.rope_theta
    dim = getattr(config, "head_dim", None) or config.hidden_size // config.num_attention_heads
    inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2, dtype=torch.float) / dim))
    return inv_freq.to(device), 1.0
```

## Common Pitfalls

### Pitfall 1: Fixing a model where the instrument cannot see it
**What goes wrong:** the handler-level DNABERT-2 fix passes manual testing but the census re-probe stays red, so no flip is possible and the phase's own D-02 blocks its own goal.
**Why:** the census load program uses plain `Auto*` (`scripts/census_compat.py:887-985`).
**How to avoid:** decide the visibility route in the plan (census pre-load installer call vs rung), and prove it with a `--entries` probe, not a manual script.
**Warning signs:** "it loads in my notebook" while `--run --entries` still records `skip`.

### Pitfall 2: Trusting the todo's measured values
**What goes wrong:** the GENA-LM fix is implemented with `torch.arange(type_vocab_size)` and the census probe greens the *load* but the forward dies with `IndexError: too many indices for tensor of dimension 1` — and the published wording claims "the checkpoint is damaged", which is false.
**Why:** the todo's value came from one observed garbage word; the buffer's content is uninitialized memory and changes per run.
**How to avoid:** reset to `torch.zeros(position_ids.size())`; word the evidence as a construction-path repair; prove both with an offline test asserting shape and range.

### Pitfall 3: A green load that publishes as `verified-tf5`
**What goes wrong:** `compat_verdict` maps green → `verified-tf5` unless `SHIM_RESTORED_LOADS` says otherwise, so the public page tells users the model "works as-is" — the exact claim D-03 forbids.
**How to avoid:** add the four repos to `SHIM_RESTORED_LOADS` and to the gate's independent copy in the same commit as the re-probe; assert the resulting distribution.

### Pitfall 4: Stale dispositions and fail-closed mapping
**What goes wrong:** a changed verdict drops the old `skip` disposition (`merge_records`), and a non-green, non-rep-less record (CrossDNA!) makes `compat_verdict` raise, so `--write-registry` aborts mid-campaign.
**How to avoid:** sequence the plan as *probe → inspect artifact → author dispositions if needed → write-back*, and treat the ValueError as a designed stop, not a bug.

### Pitfall 5: `inspect.getsource` on exec'd/remote classes
**What goes wrong:** a defect-detection guard based on `inspect.getsource` raises `OSError` for classes without a readable source file, taking the whole load down.
**How to avoid:** wrap detection in `try/except (OSError, TypeError)` and treat "cannot read source" as "no defect" (never repair blind).

### Pitfall 6: Pulling `ROPE_INIT_FUNCTIONS` by name into the remote module
**What goes wrong:** reassigning `transformers.modeling_rope_utils.ROPE_INIT_FUNCTIONS = {...}` leaves the remote module holding the old dict object (bound at import).
**How to avoid:** mutate in place (`setdefault`) so every holder sees the new key.

### Pitfall 7: `pip install gpn` as literal guidance
**What goes wrong:** the docs send users to a package that refuses to install on Python 3.11/3.12, pins `transformers==5.15.0`, and does not even satisfy `import gpn.model`.
**How to avoid:** publish the measured caveats (§Fix 5); keep the repository/git install line the docs already use.

### Pitfall 8: Doc-gate and installer-roster collisions
**What goes wrong:** a new `_patch_*` rung without the roster update fails `test_apply_patches...`; a handler-named rung in evidence fails `test_shim_required_evidence_names_rung`; a broken-count pin left at 7 fails on the first re-probe.
**How to avoid:** make the "companion edits" table a checklist in the plan and run `tests/models/` + `tests/utils/` before every claim.

### Pitfall 9: Editing `model_info.yaml` by hand
**What goes wrong:** REG-03 forbids YAML round-trips and the registry is the sole parser; the writer is anchored-insertion and idempotent (dry-run first).
**How to avoid:** always `--write-registry` then `--apply`; never touch the yaml in an editor.
