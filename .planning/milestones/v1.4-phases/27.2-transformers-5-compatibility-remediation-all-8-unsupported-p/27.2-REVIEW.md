## Warnings

### WR-01: Published docs screenshots embed the capture machine's username via absolute cache paths

**File:** `docs/pic/tui/env.svg:201-202`, `docs/pic/tui/wizard.svg:205-206`
**Issue:** The regenerated TUI screenshots render the env screen's disk-space probe verbatim, embedding `/home/forrest/.cache/huggingface/hub` and `/home/forrest/.cache/modelscope` into assets published to the GitHub Pages docs site. This discloses the capture machine's local username and makes the shipped asset machine-specific. `git show 838535b5:docs/pic/tui/env.svg` confirms the same two occurrences existed before regeneration — the regeneration carried the defect forward rather than introducing it — but both files are inside this delta scope and the review brief explicitly names leaked absolute paths as a gross anomaly to check. The other four regenerated SVGs are clean.
**Fix:** During headless capture, point the caches at a neutral path so the rendered probe text is generic, e.g. run the capture with `HF_HOME=/tmp/dnallm-docs/hf` and `MODELSCOPE_CACHE=/tmp/dnallm-docs/ms` (or a `~`-relative display), then regenerate the six SVGs. Alternatively post-process the exports to replace `/home/<user>/` with `~/`.

## Info

### IN-01: `_guide_section` end-detection can silently satisfy the negative regression pin

**File:** `tests/models/test_compat_docs_consistency.py:589-604`
**Issue:** The next-heading scan `re.search(r"^#+\s", guide[match.end():], ...)` treats any `#`-prefixed line as a section boundary — including `#` comment lines inside fenced code blocks — and does not recognize setext headings (`Title\n====`). For the current guide (pure ATX headings, no `#` lines inside its two bash fences) the slicing is correct. Latent risk: if the GENA-LM section later gains a code fence whose `#` comment line lands between the heading and the phrase being watched, the section truncates early. The positive pins (`"zeros"`, `"non-persistent"` — both in the first paragraph) would still pass, while the negative pin `assert "damaged published" not in section` (line 635) would false-pass even though the regression text is present in the real section. Failure direction is otherwise fail-closed, so this is a robustness note, not a current bug.
**Fix:** When scanning for the next heading, skip regions inside triple-backtick fences, e.g. strip fenced blocks first: `re.sub(r"```.*?```", "", guide, flags=re.DOTALL)` before the `^#+\s` search.

### IN-02: mkdocs/README reads lack the fail-closed guard used everywhere else in the gate

**File:** `tests/models/test_compat_docs_consistency.py:667,674,686`
**Issue:** `test_mkdocs_nav_lists_the_guide`, `test_mkdocs_nav_entry_follows_model_compatibility`, and `test_readme_links_both_guides_and_states_support_varies` call `MKDOCS_PAGE.read_text(...)` / `README_PAGE.read_text(...)` directly, unlike `_read_guide()` / `_read_page()` which check `is_file()` and emit a descriptive `pytest.fail`. A missing file still fails CI (FileNotFoundError), so the fail-closed posture is preserved in effect — this is a consistency nit: the gate's own convention (module docstring: "a missing page ... is a test failure, never a skip") is implemented with a clearer message for the two doc pages but not for `mkdocs.yml`/`README.md`.
**Fix:** Route both through small `_read_mkdocs()` / `_read_readme()` helpers mirroring `_read_guide()`'s `is_file()` + `pytest.fail(f"... missing: {path}")` pattern.
