<objective>
Rewrite exactly one tool body — `_get_all_available_models` at `dnallm/mcp/server.py:818` — so it serves the full packaged registry listing (all 236 entries, via `all_entries()` sorted lab-first by `sort_key_lab_first`) with a three-boolean overlay (`configured` / `enabled` / `loaded`) composed from state that already exists on the server, closing issue #64's registry-consumption half (MCP-02). Purpose: today the tool named "get all available models" returns only the 3-5 configured models — an MCP client's model menu lies about what it can call. After this plan the menu is the registry's truth, and each row says whether it is configured, enabled, or loaded right now.
Output: `dnallm/mcp/server.py` (one function + one import line + docstring) + `tests/mcp/test_server_streaming.py` (two tests rewritten, overlay matrix added). `dnallm/mcp/client.py` and `tests/mcp/test_client_sdk.py` are untouched — the client passes the payload through, and their tests prove it.

Recorded plan-time decisions (planner discretion from 26-CONTEXT.md, exercised here):
- **Row shape (lean by design):** each row = `repo_id`, `task_type`, `is_lab`, `configured`, `enabled`, `loaded`, plus `server_config_key` on configured rows only. Depth (num_labels, label_names, metrics) stays behind `get_model_info` / `list_models_by_task_type` — D-16's compact-menu intent; no filters added this phase (CONTEXT discretion explicitly defers optional task_type/intent filters).
- **Status word mapping (D-16's status column):** `loaded` > `enabled` > `disabled` > `available` — a loaded row says "loaded" even if also enabled; configured+enabled+not-loaded says "enabled"; configured+disabled says "disabled"; unconfigured says "available" (downloadable from a hub, callable after configuration).
- **Unmatched configured models** (a server key resolving to no registry entry) surface as `unmatched_configured: list[str]` on the response — visible at the tool boundary, never a phantom row (the Phase-26-01 checker's MODEL_NOT_IN_REGISTRY finding is the durable backstop).
- **Truncation:** none at the current 236-entry size (~19 KB text; within MCP message norms); recorded, revisit at ~10x registry growth.
- **Registry import placement:** module-level `from ..models.registry import all_entries, is_lab_model, sort_key_lab_first, try_resolve` in server.py — registry is import-light (pydantic + stdlib, lazy parse) and module-level binding gives tests a clean `dnallm.mcp.server.all_entries` patch seam; the real (unpatched) registry powers the 236-row tracer test since it needs no network.
</objective>
