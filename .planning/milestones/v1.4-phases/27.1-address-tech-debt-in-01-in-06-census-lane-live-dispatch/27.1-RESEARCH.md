## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Word-boundary truncation | switching to `textwrap.shorten` | extend the existing helper in lockstep | `textwrap.shorten` collapses whitespace and rewrites the tail with its own placeholder — changes every currently-committed cell and breaks byte-stability; the repo already owns a deterministic 100-char bound |
| Version-pinned uv install | a bespoke downloader for the uv tarball | skip-if-present guard over the box's provisioned uv | the box already carries mirror-configured uv 0.13.6; a pinned downloader adds maintenance for a path that should never execute on this box |
| Workflow registration | API hacks / workflow re-creation | one registration commit on `main` carrying the byte-identical file | GitHub resolves dispatchables from the default branch; identical bytes on both branches make the file-version ambiguity moot |
| Balance-aware cut | regex gymnastics over the whole fragment | a small loop: while unbalanced, cut before the last unclosed opener, then strip trailing separators | verified against the real evidence string this session; handles nesting and the no-balanced-prefix fallback deterministically |

**Key insight:** every fix here is a small change to an existing, test-pinned mechanism. The risk is never the algorithm — it is forgetting a lockstep twin, a fast-lane pin, or the committed-page regeneration.

## Common Pitfalls

### Pitfall 1: The reviewer's minimal IN-01 fix does not close the finding
**What goes wrong:** `cut = cut.rstrip("(:[,; ")` before appending the ellipsis still leaves the DNABERT-2 fragment with one unclosed `(`.
**Why it happens:** rstrip only removes *trailing* punctuation; the `(` opened by `(rebuild_alibi_tensor` has words after it.
**How to avoid:** verified this session against the real cause clause `remote bert_layers.py builds its ALiBi tensor eagerly in __init__ (rebuild_alibi_tensor line 399: torch.Tensor(list) stays on cpu while torch.arange lands on meta)` (163 chars, from `[VERIFIED: dnallm/models/model_info.yaml:276]`):
```text
word-boundary cut @100 : 'remote bert_layers.py builds its ALiBi tensor eagerly in __init__ (rebuild_alibi_tensor line 399:'
after reviewer's rstrip   : 'remote bert_layers.py builds its ALiBi tensor eagerly in __init__ (rebuild_alibi_tensor line 399'   <- still 1 unclosed '('
balance-aware cut         : 'remote bert_layers.py builds its ALiBi tensor eagerly in __init__'                                    <- balanced
```
Implement balance-aware truncation: after the word-boundary cut, while `cut.count("(") > cut.count(")")` or `cut.count("[") > cut.count("]")`, cut before the last unclosed opener; then strip trailing `(:[,; ` characters; then append `…`. Apply identically in generator AND gate `_bound_fragment`.
**Warning signs:** a new unit test asserting the DNABERT-2-shaped input yields a balanced fragment; the regenerated page's DNABERT-2 cell ending `__init__…)`.

### Pitfall 2: Dispatch is impossible until the workflow lands on main (verified 404)
**What goes wrong:** `gh workflow run census_compat.yml --ref v1.4` fails — the workflow has never existed on the default branch.
**Why it happens:** GitHub registers dispatchable workflows from the default branch only.
**How to avoid:** verified live this session: `gh workflow view census_compat.yml` → `HTTP 404: workflow census_compat.yml not found on the default branch`; `gh workflow list --all` shows only CI, Docs Validation, feasibility, Publish to PyPI, Dependabot, pages-build-deployment; `git show origin/main:.github/workflows/census_compat.yml` fails. Land one registration commit on `main` carrying the byte-identical file, then dispatch `--ref v1.4` (main's tree has no census script — dispatching `--ref main` would be red by construction).
**Warning signs:** any dispatch attempt before the registration commit exists on origin/main.

### Pitfall 3: IN-04's kwargs hole has a second, nastier shape under the classmethod binding
**What goes wrong:** naively "resolving the receiver from args first" can materialize onto the CLASS, not the model.
**Why it happens:** when the original binds as a classmethod, the wrapper is installed as a classmethod — a kwargs-only caller injects `cls` into `args`, so `args[0]` is the class, and `receiver = args[0]` calls `cls.get_expanded_tied_weights_keys(...)` unbound. transformers 5.17 ships the method STATIC (so today only the skip happens), but the wrapper deliberately adapts to both shapes.
**How to avoid:** prefer the kwargs receiver: if `model`/`self` is present in `kwargs`, that object is the receiver regardless of binding; only fall back to positional resolution when no kwargs receiver exists; never materialize when no plausible receiver object was found (delegate as today). Quoted verbatim, the current hole `[VERIFIED: dnallm/utils/transformers_compat.py:1650-1661]`:
```python
    def _finalize_model_loading(*args, **kwargs):
        if args:
            receiver = args[1] if binds_class and len(args) > 1 else args[0]
            _materialize_tied_weights_bookkeeping(receiver)
            # The same skipped-entry receivers never ran the init_weights
            # wrapper that installs the legacy tie_weights arity bridge, and
            # 5.x from_pretrained calls model.tie_weights(missing_keys=...,
            # recompute_mapping=False) after loading -- bridge it here too
            # (measured live on the bare remote Caduceus backbone of
            # PlantCaduceus_l32; the bridge self-guards per signature).
            _bridge_legacy_tie_weights(receiver)
        return _tied_bookkeeping_original_finalize(*args, **kwargs)
```
**Warning signs:** new test calling `PreTrainedModel._finalize_model_loading(model=..., load_config=..., loading_info=...)` and asserting `hasattr(model, "all_tied_weights_keys")` AND that the class itself gained no attribute.

### Pitfall 4: IN-05's `UV_VERSION` suggestion is refuted — and the box's uv is being replaced nightly
**What goes wrong:** planning a `UV_VERSION=...` env var pin; it does not exist.
**Why it happens:** the reviewer assumed the installer's older API.
**How to avoid:** fetched `https://astral.sh/uv/install.sh` this session and inspected it: no `UV_VERSION`/`REQUESTED_VERSION`; supported env knobs are `UV_DOWNLOAD_URL`, `INSTALLER_DOWNLOAD_URL`, `UV_INSTALLER_GHE_BASE_URL`, `UV_INSTALLER_GITHUB_BASE_URL`, `UV_INSTALL_DIR`, `UV_NO_MODIFY_PATH`, `UV_UNMANAGED_INSTALL` `[VERIFIED: /tmp/uv-install-probe.sh, fetched 2026-10-28]` — the served script embeds the version it installs (`APP_VERSION="0.13.6"`), so "pinning" means pinning the script's bytes. ### Pitfall 5: Step-PATH assumption in the skip guard
**What goes wrong:** `command -v uv` written off as unreliable because the runner process PATH is `/usr/local/bin:/usr/bin:/bin` (verified from the live Runner.Listener process env).
**Why it happens:** the runner *process* PATH is not the *step* PATH.
**How to avoid:** empirically, nightly lanes install uv into `~/.local/bin` and LATER steps run bare `uv venv` successfully on this box (green runs for weeks; the mechanism is the actions runner prepending `$HOME/.local/bin` on Linux — the operative fact, "uv resolves in subsequent steps on this runner", is live-evidence-verified). `command -v uv` therefore succeeds on the provisioned box. If extra safety is wanted, the guard can `export PATH="$HOME/.local/bin:$PATH"` first — cheap and harmless.
**Warning signs:** a skip guard that then fails on a wiped box where no uv exists anywhere — the fallback branch covers it.

### Pitfall 6: Dispatch-time transformers drift turns the lane red BY DESIGN
**What goes wrong:** the lane's fresh venv resolves `transformers>=4.49.0,<6` to the latest 5.x; if 5.18 ships between the fix commits and the dispatch, `--verify` prints `VERSION DRIFT: installed transformers 5.18 vs committed tf_compat_tested ['5.17.0']` and exits non-zero.
**Why it happens:** version-stamped verdicts are invalidated by a transformers change — that is the lane's purpose.
**How to avoid:** dispatch promptly after the fixes land; treat a drift-red as a *correct* lane result requiring a census re-run + registry refresh (a new scope decision, not a lane bug). Today installed = committed = 5.17.0.
**Warning signs:** `VERSION DRIFT` in the dispatch log.

### Pitfall 7: Runner contention and cron windows
**What goes wrong:** the dispatch queues behind a busy runner (verified `busy: true` at probe time) or lands on the 03:00/05:30 UTC nightly crunch.
**How to avoid:** check `gh api repos/zhangtaolab/DNALLM/actions/runners` before dispatching; the lane budget is 240 minutes and the census itself measured ~302 s on the replica with warm caches.

### Pitfall 8: ruff version drift across environments
**What goes wrong:** formatting/checking with the venv's stale ruff (0.16.10) instead of the pyproject pin (0.17.1) — CLAUDE.md says 0.16.9, all three disagree (pre-existing; memory records this drift class).

## Code Examples

### IN-01: balance-aware bound (sketch — generator + gate in lockstep)
```python
# Derived from the verified truncation math this session; adapt names to each copy.
def _bound(fragment: str, limit: int = 100) -> str:
    if len(fragment) <= limit:
        return fragment
    cut = fragment[:limit]
    if " " in cut:
        cut = cut[: cut.rfind(" ")].rstrip()
    while cut.count("(") > cut.count(")") or cut.count("[") > cut.count("]"):
        opener = max(cut.rfind("("), cut.rfind("["))
        if opener <= 0:
            cut = ""
            break
        cut = cut[:opener].rstrip()
    cut = cut.rstrip("(:[,; ")
    return cut + "…"
```
