## Critical Issues

### CR-01: IN-05 skip branch drops `$GITHUB_PATH`, so the next step's `uv venv` may not find `uv`

**File:** `.github/workflows/census_compat.yml:71-77` (skip branch at lines 73-74; next step's bare `uv venv` at line 84)
**Issue:** The guard exports `PATH="$HOME/.local/bin:$PATH"` inside the `Install uv` step. A `run:` step is its own shell, so that export does not reach `Create virtual environment and install dependencies` (`uv venv`, `uv pip install -e ".[full]"`, `uv pip install --python .venv/bin/python pip`). The installer the guard replaces *did* propagate the path: the served `install.sh` writes the install dir to `$GITHUB_PATH` when that variable is set (verified in the research's own cached copy, `/tmp/uv-install-probe.sh:1482-1483`: `if [ -n "${GITHUB_PATH:-}" ]; then ensure echo "$_install_dir" >> "$GITHUB_PATH"`), and GitHub Actions sets `GITHUB_PATH` for every `run:` step. That is exactly why every sibling lane can `curl | sh` in one step and call bare `uv venv` in the next (`ci.yml:106-107` → `:122`, `docs-validation.yml:25-26` → `:41`, `feasibility.yml:56-58` → `:66`). The phase's cited evidence for the skip branch ("green nightly runs that install to that path then call bare `uv venv`") was produced by runs in which the installer still executed and therefore still wrote `GITHUB_PATH`; the skip branch removes that write. Consequence: on the first live dispatch, `command -v uv` succeeds only because of the step-local export, and the next step can fail with `uv: command not found` — reddening the single allowed dispatch (`27.1-03-SUMMARY.md`: "One dispatch only — a red run stops and is reported, never re-dispatched") for an environment reason, not census drift. The added pin `tests/test_runner_infra_contracts.py:347-392` asserts only the run-body shape, so it certifies this failure mode as correct.
**Fix:**
```yaml
        run: |
          export PATH="$HOME/.local/bin:$PATH"
          if command -v uv >/dev/null 2>&1; then
            echo "uv already provisioned: $(uv --version)"
            # Persist the path for later steps: the curl installer this guard
            # replaces wrote GITHUB_PATH, and every later step calls bare `uv`.
            echo "$HOME/.local/bin" >> "$GITHUB_PATH"
          else
            curl -LsSf https://astral.sh/uv/install.sh | sh
          fi
```
Also extend `test_uv_install_skips_provisioned_binary` to require the `$GITHUB_PATH` write in the skip branch, so an editorial revert cannot silently re-break the lane.

## Warnings

### WR-01: `_finalize_model_loading` still resolves the class as receiver on the positional-fallback path

**File:** `dnallm/utils/transformers_compat.py:1650-1675` (fallback expression at 1664-1665)
**Issue:** The new comment states "Positional resolution is the fallback, and no receiver at all means delegate unchanged (never guess)", but the fallback expression is `receiver = args[1] if binds_class and len(args) > 1 else args[0]`. When the captured original binds as a class/instance method (`binds_class` true) and the caller supplies only the injected first argument, `len(args) == 1`, so the `else` branch selects `args[0]` — which is always the class for a classmethod binding, i.e. precisely the hazard the comment says IN-04 closes. Reproduced against the exact logic: a classmethod-shaped original called without a positional model resolves `receiver` to the class. Downstream, `_materialize_tied_weights_bookkeeping(cls)` calls `cls.get_expanded_tied_weights_keys(all_submodels=False)`; on the live transformers 5.17 that attribute is an instance method `(self, all_submodels=False)`, so the call raises `TypeError` from inside `from_pretrained` before delegation, and `_bridge_legacy_tie_weights(cls)` would otherwise write `tie_weights` onto the class. The same block also conflates `cls` and `self` when choosing the wrapper binding (`binds_class = first_param in ("cls", "self")`, then `classmethod(...) if binds_class`): an *instance*-shaped original `(self, load_config, loading_info)` would be wrapped as a classmethod, so `model._finalize_model_loading(...)` passes the class as `self` and resolves `args[1]` (a `LoadStateDictConfig`) as the receiver. None of this is reachable on 5.17 (the original is a `staticmethod`, so `binds_class` is False), which is why no test exercises it — the three new IN-04 tests all run against the live staticmethod wrapper, so the classmethod branch the fix was written for is untested.
**Fix:**
```python
        receiver = None
        for name in ("model", "self"):
            candidate = kwargs.get(name)
            if candidate is not None:
                receiver = candidate
                break
        if receiver is None and args:
            if first_param == "cls":
                receiver = args[1] if len(args) > 1 else None  # never the class
            else:
                receiver = args[0]
```
and install a plain-function wrapper (not `classmethod`) when `first_param == "self"` so the instance arrives as `args[0]`. Add a test that builds a classmethod-shaped fixture class (probe `_post_init_computes_tied_weights_keys` monkeypatched True, `_finalize_model_loading = classmethod(f)`) and asserts a call carrying only `cls` neither mutates the class nor runs the receiver helpers.

### IN-02: The balance check compares paren/bracket *counts*, not nesting, and only runs on over-limit fragments

**File:** `scripts/census_compat.py:1747-1759` (gate twin `tests/models/test_compat_docs_consistency.py:171-191`, algorithm identical)
**Issue:** `while cut.count("(") > cut.count(")") or cut.count("[") > cut.count("]")` treats equal counts as balanced, so a fragment with a stray closer before an unmatched opener (`"closes ) then opens ( here ..."` → 1 vs 1) keeps its unclosed `(` and re-creates the exact symptom IN-01 fixes. Two smaller gaps: fragments at or under 100 characters return before the balance pass (`"reference (see"` → `(technical: reference (see)`), and a fragment whose last counted closer is unmatched keeps it, producing `(technical: ...))` in the cell. No committed evidence triggers any of these, and because the gate copies the same algorithm it cannot detect a shared flaw — only the direct unit tests in `tests/models/test_census_compat.py` pin the rule. Confidence that this is latent rather than live: high (all six committed broken rows were traced by hand through the new code and match the regenerated page).
**Fix:** Replace the count test with a nesting scan over `cut` (track depth for both delimiter kinds and trim at the index where depth last returned to zero with a negative-balance guard), and run the balance pass for short fragments too, e.g.:
```python
def _balanced_prefix(text: str) -> str:
    stack: list[str] = []
    pairs = {")": "(", "]": "["}
    for index, char in enumerate(text):
        if char in "([":
            stack.append(char)
        elif char in pairs:
            if not stack or stack.pop() != pairs[char]:
                return text[:index]
    return text
```

### IN-04: Pre-census step failures produce no uploaded evidence, contrary to the upload step's stated intent

**File:** `.github/workflows/census_compat.yml:150-160` (directory re-created only at line 146)
**Issue:** The upload step is `if: always()` and its comment says "the artifact is the deliverable, especially on failure — a red run with evidence beats a green run without it", but `census-artifacts/` is re-created only inside the census `run` step (line 146) because `actions/checkout`'s default `clean` removes the pre-checkout `mkdir`. Any failure in the intervening steps (`Install uv`, the venv/mamba install, runner-identity) therefore reaches the upload with neither `census-fresh.json` nor `gpu_absent.marker`, and `if-no-files-found: warn` swallows it. Pre-existing (the CR-01 mkdir relocation introduced it), but it is the diagnosability path for the one-shot DISP-01 dispatch.
**Fix:** Add a cheap always-run marker step before the upload (or move `mkdir -p census-artifacts` into a step that runs after checkout with `if: always()`), e.g. `run: mkdir -p census-artifacts && echo "run started $(date -u +%FT%TZ)" > census-artifacts/run_started.marker`, and include that marker in the upload `path:` list.
