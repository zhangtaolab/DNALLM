## Deviations from Plan

**1. [Rule 3 - Blocking] Task C behavior tests: the plan's dotted monkeypatch string silently missed**
- **Found during:** Task C verification (first run of `pytest tests/models/test_plant_helixseek_smoke.py -m "not slow"`)
- **Issue:** the plan prescribed
  `monkeypatch.setattr("tests.models.test_plant_helixseek_smoke.load_model_and_tokenizer", fake)`,
  but the repo's `tests/` tree has no `__init__.py` anywhere, so under pytest's prepend import mode
  the executing module is `test_plant_helixseek_smoke` (basename) while the dotted target lazily
  creates and patches a *second* namespace-package module object — the patch landed on the wrong
  object and both behavior tests invoked the real loader (which succeeded from the warm local
  ModelScope cache; no ~1.9 GB download occurred, weights loaded from cache in <1 s).
- **Fix:** patch the module object that actually owns `_load_with_fallback`:
  `monkeypatch.setattr(sys.modules[_load_with_fallback.__module__], "load_model_and_tokenizer",
  fake)`, with a comment explaining the import-mode hazard. Works under any import layout.
- **Files modified:** tests/models/test_plant_helixseek_smoke.py
- **Verification:** 7 not-slow tests pass, hermetically (3.3 s, no loader logs).
- **Commit:** 1219f0f

**2. [Rule 1 - Lint] ruff `pytest-assert-in-except` (PT) rejected the chain-walk unit tests as first written**
- **Found during:** Task C verification
- **Issue:** the two boundary-wrap unit tests used nested try/except with `assert
  _is_environment_error(wrapped)` inside the `except` block — PT forbids asserting on an
  except-bound exception variable.
- **Fix:** construct the wrap by setting `wrapped.__cause__` directly, which is exactly what
  `raise ... from ...` does; semantically identical for the chain walk, and clearer.
- **Files modified:** tests/models/test_plant_helixseek_smoke.py
- **Verification:** `ruff check` clean; tests still pass.
