## Spacing Scale

The template's "must be a multiple of 4" rule is a pixel rule and does not transfer to a character
grid. **The as-built unit is one terminal cell.** At a typical 8×17 px cell, 1 cell ≈ 8 px and 2
cells ≈ 16 px horizontally — the declared values map onto the 8/16 rungs of the usual scale, but
they are declared in cells because that is what the CSS says.

| Token | Value | Usage |
|-------|-------|-------|
| `flush` | 0 cells | No gap: first section under the status line (`#config-section-task`), output row margin |
| `tight` | 1 cell | One blank row between blocks; vertical page padding (`padding: 1 2`) |
| `loose` | 2 cells | Horizontal page padding (`padding: 0 2`), button gaps (`margin-left: 2`) |
| `fill` | `1fr` | The one flexible split: `#config-form` / `#config-side`, and every `*-body` height |

Only these three cell values appear anywhere in the CSS. No other spacing value may be introduced
without amending this table.

**Row budgets** (a terminal's vertical spacing is a row count, so these are declared as part of the
spacing contract):

| Selector | Budget | Rationale |
|----------|--------|-----------|
| `#config-errors` | `height: auto`, **no `max-height`, no `overflow-y`** | Contract-bearing (25-13): every row the pane holds is laid out; `#config-side` is the single scroll surface |
| `#config-preview` | `max-height: 24` | **Deferred** — same inert-overflow class as CR-02; see D-5 |
| `#data-findings` | `max-height: 14` | A `DataTable` scrolls itself, so the cap is a real budget |
| `#suitability-verdicts` | `max-height: 12` | Same |
| `#suitability-listing` | `max-height: 14` | Same |

**Viewport contract.** The smallest supported screen is **80 columns × 24 rows**, and four tests
assert against exactly that size:

| Test | What it asserts at 80x24 |
|------|--------------------------|
| `test_the_panel_is_usable_at_80x24` (data) | The check button is inside the body; the findings table is at least header + 1 row and its first row is above the body bottom |
| `test_at_80x24_the_plain_error_fits_and_the_raw_one_is_a_press_away` (config) | The error pane lays out all 17 rows of the worst-case sentence (25 with details), its last laid-out row carries `binary_classification`, and the side column scrolls that row into view |
| `test_the_task_type_legend_is_reachable_at_80x24` (suitability) | The legend, the check action and the use action are each contained in the body after `scroll_to_widget` |
| `test_the_hinted_form_stays_legible_at_80x24` (config) | The task-type input is inside the form **before any scrolling** in the clean state and with an error showing; its hint starts on the row directly below it |

Measured geometry at 80x24 (post-25-13): the config form is 38 columns / 11 rows clean and 10 rows
with an error; the side column is 40 columns with a 32-column text run; the task-type input sits at
y=7 clean and y=8 with an error (it was y=23 before the fix); one bad `task_type` renders a 489-
character sentence plus a 14-character field path over 17 wrapped rows.

Exceptions: none beyond the row budgets above. Touch-target sizing does not apply (keyboard-first,
and mouse clicks land on whole buttons).

## Typography

There is no font and no point size. Typography here is the cell grid, the wrapping rule, and the
glyph choice.

| Role | Size | Weight | Line height |
|------|------|--------|-------------|
| Body | 1 cell | regular (default) | 1 row |
| Muted help | 1 cell | regular | 1 row |
| Italic status | 1 cell | italic | 1 row |
| Heading | 1 cell | bold | 1 row |

Declared sizes: **1** (the terminal cell). Declared weights: **2** (regular, bold). A third
treatment — italic — is used for status/detail lines and is declared as a treatment, not a weight.
See divergence D-2: the template asks for 3–4 sizes and exactly 2 weights; a cell grid has one
size and the shipped app uses regular + bold + italic.

**Wrapping and length rules**

- Text word-wraps at the widget's column width. **Nothing is truncated with an ellipsis and nothing
  is clipped** — the only two legal overflow answers are "wrap" and "scroll".
- A single copy line in `copy.py` must stay **≤ 74 columns** (pinned by `tests/tui/test_copy.py`),
  which is the width `#suitability-body` gives the legend at 80x24 once its scrollbar shows.
- The measured wrap column for help and error text inside the config split at 80x24 is **32
  columns**.
- Multi-row copy is contract-bearing and its row cost is measured, not estimated:
  `CONFIG_FIELD_HINTS[("task","task_type")]` is **453 characters → 15 rows**;
  `CONFIG_FIELD_HINTS[("lora","target_modules")]` is **226 characters → 8 rows inside a 9-row
  viewport**; `CONFIG_ERROR_MESSAGES[("task","task_type","not_an_allowed_value")]` is **489
  characters → 17 rows**, and **25 rows** with the raw detail line on.
- `SUITABILITY_TASK_LEGEND` is **10 rows**, longest line **74 columns**.

**Glyphs.** ASCII and common punctuation only: `…`, `—`, `→`, `"`, `'`. No box-drawing, no emoji,
no Nerd Font glyphs — the Windows CI leg must render identically.

**Text treatments by selector** (the complete list, so a new style cannot appear unnoticed):

- `text-style: bold` — `#env-title`, `#data-title`, `#data-summary-heading`,
  `#data-charset-heading`, `#data-findings-heading`, `#suitability-title`,
  `#suitability-verdicts-heading`, `#suitability-listing-heading`, `#config-title`,
  `#config-errors-heading`, `#config-preview-heading`, `#config-kept-as-is-heading`,
  `#config-heading-{task,model,finetune,inference,lora}`, `#download-title`,
  `#download-model-label`, `#summary-title`, `#summary-model-heading`,
  `#summary-config-heading`, `#entry-title`.
- `text-style: italic` — `#data-status`, `#data-no-findings`, `#suitability-status`,
  `#suitability-detail`, `#config-status`, `#config-facts-note`, `#download-availability`,
  `#download-elapsed`, `#entry-status`.
- `color: $text-muted` — exactly two selectors: `.config-hint` (the 12 field hints) and
  `#suitability-task-legend`.
- Everything else is default body text.

## Color

The app defines **no hex value**. Color is Textual's `textual-dark` theme, referenced through theme
variables; the only two variable references in the whole CSS are `$text-muted` (above) and the
`variant="primary"` button style.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | theme `$background` (textual-dark) | Every screen body and scroll surface; no explicit rule is written, so the theme default holds |
| Secondary (30%) | theme panel/surface defaults | `Header`, `Footer`, `DataTable` chrome, un-styled `Horizontal`/`Vertical` containers |
| Accent (10%) | theme `$primary`, only via `variant="primary"` | The seven accent positions listed below — nothing else |
| Muted | `$text-muted` | The 12 field hints and the suitability task legend only |
| Destructive | **none** | No destructive semantic color is declared and no destructive action exists; see divergence D-3 |

**Accent reserved for** (the complete list — seven accent positions, one per screen's forward
action; the route control is a pair, so eight button ids in total and exactly one is primary at any
moment):

1. `#env-continue` — "Continue to your data"
2. `#entry-from-data` — "Start from my data"
3. `#data-check` — "Check this data"
4. `#suitability-intent-finetune` / `#suitability-intent-predict` — the **active route only**;
   choosing the other route returns the previous one to `variant="default"`
5. `#config-save` — "Save this config"
6. `#download-start` — "Download this model"
7. `#summary-quit` — "Quit the wizard"

Accent is explicitly **not** used for: `escape`/Back, `#data-skip`, `#data-continue`,
`#config-continue`, `#download-cancel`, `#download-retry`, `#download-skip`,
`#config-error-details`, table cursors, headings, labels, or hints.

## Copywriting Contract

All copy is English, plain language, written for a biologist (D-10; owner directive 2026-10-21).
Technical identifiers — model names, section/field paths, reason codes, hub names, versions, file
paths, YAML keys and values — are shown **verbatim** and are never translated, rewritten or
title-cased by the shell.

| Element | Copy |
|---------|------|
| Primary CTA (env) | Continue to your data |
| Primary CTA (entry) | Start from my data |
| Primary CTA (data) | Check this data |
| Primary CTA (suitability) | Check these models → Use this model |
| Primary CTA (config) | Save this config → Continue to the download |
| Primary CTA (download) | Download this model |
| Primary CTA (summary) | Quit the wizard |
| Empty state heading | `Your data` with `No data provided yet.` — the step is optional |
| Empty state body | "No data is fine. The next page will judge models from the model and your task alone. The length and character checks stay empty until you add data." |
| Empty state (findings) | "No problems found in this data." (the explicit all-clear, never an empty table) |
| Empty state (config clean) | Error pane empty, details control disabled, label "Show details from the check" |
| Empty state (no model) | "No model was chosen in this run, so there is nothing to download. Here is your summary." |
| Empty state (no config) | "No config file was saved in this run." |
| Error state | Plain sentence first, every time; never an exception class, never a reason code: e.g. "The download did not finish. Check your internet connection and try again." / "We could not finish checking the graphics card and the free disk space. The rest of this page still works and you can keep going." |
| Error state (config) | `section.field → plain sentence` per problem, in the core's fixed order; the raw text is one press away under "Show details from the check"; saving stays off until the list is empty |
| Destructive confirmation | **None in this phase.** No destructive action exists. The two irreversible-ish acts are handled by gating and honest wording, not a dialog: saving is disabled until validation is clean, and stopping a download says "Stopping — this download attempt will finish first." |
| Navigation affordance | "Press q at any time to quit." on every screen |
| Missing-extra error | "The terminal wizard needs an optional package that is not installed yet. Install it with: pip install \"dnallm[tui]\"" — printed by the CLI, never a traceback |

### The eight task-type glosses (contract-bearing)

`TASK_TYPE_GLOSSES` is the single ordered source; every task-type sentence and every legend line is
composed from it. These exact eight values and glosses must appear, in this order, wherever the
vocabulary is explained:

| Value (verbatim) | Gloss (verbatim) |
|------------------|------------------|
| `embedding` | a list of numbers for a whole sequence, to compare or search |
| `mask` | fill in DNA letters that were hidden from the model |
| `generation` | write out new DNA letters |
| `binary` | one yes/no answer for the whole sequence |
| `multiclass` | one answer chosen from several classes |
| `multilabel` | several yes/no answers at once |
| `regression` | a number, such as a measured value |
| `token` | one label for each DNA letter |

The vocabulary is rendered at **four sites**: the static suitability legend
(`#suitability-task-legend`, which survives typing), the `task_type` field hint, the
`not_an_allowed_value` error sentence, and the `task_type_required` error sentence. A drift test
reads the live `TaskConfig` schema pattern and fails if the copy set and the core's set diverge.

### Other contract-bearing sentences

| Constant | Value | Why it is contract |
|----------|-------|--------------------|
| `CANCEL_PENDING_NOTE` | "Stopping — this download attempt will finish first." | A thread cannot be interrupted; claiming "cancelled" would be false |
| `CONFIG_SAVE_DISABLED_REASON` | "Saving stays off until the list under \"What needs fixing\" is empty, so a broken config can never be written." | The gate's own explanation |
| `CONFIG_READONLY_FACTS_NOTE` | "from the model checkpoint; loading uses this value" | Explains why `num_labels`/`label_names`/`threshold` are disabled (D-12) |
| `HOSTING_NOT_VERIFIED` | "hosting not verified" | D-05: an unprobed row states exactly what is known |
| `UNKNOWN_STILL_DOWNLOADABLE` | "We have not confirmed where this model is hosted. You can still choose it: the download picks the most likely place for this model, and you can try again if that does not work." | UNKNOWN must never read as unavailable (D-06) |
| `SUMMARY_MODEL_STOPPED` | "You stopped the download. The model files may be incomplete — you can download them again later; nothing you set up is lost." | A stopped transfer may have written part of the files (WR-03) |
| `CONFIG_DEFAULT_EXPORT_NAME` | `dnallm_config.yaml` | The one default the wizard supplies |

## Interaction Contract (as built)

**Screen stack** — one `Screen` class per step, pushed in this order:

`EnvScreen` → ( `EntryScreen` if no `--config` ) → `DataScreen` → `SuitabilityScreen` →
`ConfigScreen` → `DownloadScreen` → `SummaryScreen`.

`dnallm preflight --config PATH` skips `EntryScreen` and opens `ConfigScreen` on that path. The
path is stored on `WizardState` and never read by a screen; only the core's `edit_config` opens it.

**Keys**

| Key | Where | Effect |
|-----|-------|--------|
| `q` | every screen | Quit the wizard (`App` binding; the summary hides it from the footer) |
| `escape` | config, download | Back one step; disabled while a download is running |
| `p` | suitability | Ask the core to re-check the focused row's hosting (one row, on demand) |
| arrows / Enter | suitability listing, both tables | Move the row cursor; Enter on a listing row selects that model |

**Focus and reachability**

- Each screen keeps its primary action reachable; the strictest rule is the config form: the first
  interactive control (`#config-field-task-task_type`) is inside the viewport at 80x24 before any
  scrolling, in both the clean and the error state.
- The data panel keeps its check action inside the visible body at 80x24.
- The suitability panel accepts scroll-to-reach for the legend, check and use controls at 80x24
  (measured reachable), and for the use action with a large report (WR-09, deferred).

**Background work**

- Every blocking core call runs in a Textual thread worker (`@work(thread=True, exit_on_error=False)`)
  or, for downloads, on a dedicated daemon thread. The event loop never blocks.
- Workers cross back to the UI **only** through typed messages (`post_message`), enforced by an AST
  guard: a `@work` body may call nothing but `post_message` on `self`.
- A worker failure becomes one plain-language status row (`WorkerFailed`) — never a traceback and
  never an app exit.

**Progress and cancellation**

- Download progress arrives from the downloader's own callbacks, clamped non-decreasing inside one
  measurement; a new attempt or a new file restarts the measurement.
- Cancel is **cooperative**: it takes effect before the next attempt, an attempt already talking to
  the hub finishes, and the status line says so. Quitting is never blocked, and the process may exit
  while a hub call is still in flight.
- Download is sequential and single-model; there is no queue and no persistence.

**Validation**

- Every field change revalidates the whole working mapping through the core's shared
  `validate_sections` path; errors are listed in the core's fixed order and never re-sorted.
- The working mapping is a deep snapshot taken on the UI thread before each worker dispatch, so a
  keystroke cannot mutate what the worker is reading.
- A local availability batch may only repaint the report already on screen; an arrival from an older
  check generation is dropped.

**Writes**

- The wizard writes exactly one file: the config, through the core's `edit_config(...,
  output_path=...)`, and only while the error list is empty and the output path is non-empty.
- No screen imports YAML or writes a file itself.
