## Objective

Deliver the core-owned environment fact collector (D-02) that the wizard's first panel renders: `dnallm/utils/env_info.py` with version, device/VRAM, and cache-root disk rows, split into a torch-free fast path (`collect_versions`, `collect_disk`) and a torch-inside-the-body slow path (`collect_device`), composed by `collect()`.

Purpose: TUI-03 forbids logic in screens; every environment fact must therefore come from a core function that degrades instead of raising, and the split lets the env panel paint version rows before torch loads (D-01).

Output: the collector module and its unit suite.

## Locked in-plan decisions

- **Three functions, not one, so D-01's "instant version rows, later device rows" is implementable without a screen-side branch:** `collect_versions()`, `collect_device()`, `collect_disk()`, and `collect()` = the ordered composition.
- **Cache roots are resolved with stdlib only.** The HF side honors `HF_HOME` then `HF_HUB_CACHE` then `~/.cache/huggingface`; the ModelScope side honors `MODELSCOPE_CACHE` then `~/.cache/modelscope`. No hub library import is needed to compute a disk row.
- **Rows are data, not formatted paragraphs:** `EnvRow(key, label, value)` keeps the screen free to render; the plain-language phrasing lives in the label/value strings produced here.
- **Categories are finite and closed** (D-03): no driver version, CPU model, or RAM rows.
