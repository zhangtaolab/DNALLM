## Objective

Deliver the config step (survey R4): a structured form over the five core sections that generates a config from the selected model or edits an existing YAML, revalidates every field change through the shared `validate_sections` path, lists every error as `section.field -> plain-language message`, previews the exact YAML that would be written, and enables saving only when the list is empty — plus the dual-entry choice and the `--config` direct jump.

Purpose: SC3 — the user leaves with a validated config, and no invalid file is ever written.

Output: two additive core fields/functions that make the raw mapping and its YAML rendering visible to a shell, the config screen, the entry screen, and tests.

## Locked in-plan decisions

- **Two small core additions are required by the locked decisions and are additive:**
  - `GeneratedConfig.raw` (default empty dict) carrying the assembled/patched raw mapping — without it a shell cannot preserve ia3/vep/sweep (D-11) or preview what `_dump_yaml` writes.
  - `render_yaml(config) -> str` — one serializer shared with `_dump_yaml`, so the preview and the written file can never diverge; the screen never touches yaml.
  Both keep the frozen-model contract (a defaulted field) and add tests in the same change.
- **Working-mapping flow:** `generate_config(model, task_type=...)` -> `result.raw` becomes the screen's working mapping; every field change calls `edit_config(working, patch={section: {field: value}})` -> new `result.raw` + errors.
- **Read-only facts come from the generation result** (`result.raw["task"]` fields), not from a registry lookup in the screen.
- **Five sections only** in the form (`task`, `model`, `finetune`, `inference`, `lora`); any other section in `raw` is shown in a read-only "kept as-is" list.
- **Default export name:** `dnallm_config.yaml` in the current directory (discretion; the user can change the path before saving).
