## Objective

Give the wizard its entry point and its first panel: a `dnallm preflight` click subcommand that lazily imports the TUI with a friendly missing-extra message (TUI-02), the composition root `DNALLMPreflightApp`, shared wizard state, the copy module, and the environment panel rendering `dnallm.utils.env_info` (TUI-03) with instant version rows and worker-filled device/disk rows.

Purpose: this is the first observable user path (TUI-02's launch contract) and the first screen, so it establishes the app/state/navigation skeleton every later screen extends.

Output: CLI command, app shell, state, copy inventory, env screen, CLI and Pilot tests.

## Locked in-plan decisions

- **App-level injected seams:** `DNALLMPreflightApp(collector=<module-like>, prober=None, downloader=None, config_path=None)`. `collector` defaults to the `dnallm.utils.env_info` module and must expose `collect_versions`, `collect_device`, and `collect_disk` (tests inject a fake object with the same three names). Screens call `self.app.collector` / `.prober` / `.downloader`, so Pilot tests run network-free without monkeypatching module attributes.
- **One `WizardState` dataclass** on the app is the only shared mutable state; screens read/write fields, never re-derive reports.
- **Copy lives in `dnallm/tui/copy.py`** as module constants, making the phase-end plain-language review a single-file read and any copy test a simple assertion.
- **`markup=False` for every non-literal string** rendered into Static/Label (Pitfall 5), with the reason recorded in a comment at the helper.
- **`--config` is stored, not loaded** here; the config panel owns YAML loading through the preflight safe-loader path.
