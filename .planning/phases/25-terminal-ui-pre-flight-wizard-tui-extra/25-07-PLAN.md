## Objective

Deliver the suitability step: render `check_compatibility` verdicts and the intent-routed listing with lab-first order preserved, compute offline local availability for every visible row, remote-probe only the lab-first shortlist, allow an on-demand probe per row, and route the selected model into wizard state — with the WR-01 third-party hosting honesty rule (D-05) and UNKNOWN-is-downloadable (D-06) enforced.

Purpose: TUI-05's panel is where the wizard earns trust; every fact must come from the core, and every degraded fact must be shown honestly rather than hidden.

Output: one small core addition (`local_availability`), the suitability screen, copy, and tests.

## Locked in-plan decisions

- **Core addition is deliberate and minimal:** the D-04 clause "local cached states for ALL visible rows" cannot be satisfied by screen-side path checks without violating the presentation-only rule, so `dnallm/preflight/availability.py` gains `local_availability(model)` wrapping the existing three-way detection (`_probe_cached_local`) and returning UNKNOWN when nothing is cached. No network, no new enum, no behavior change to `probe_availability`.
- **Shortlist policy stays in the core:** the screen calls `check_compatibility(..., prober=self.app.prober, probe_shortlist=20)`; it does not iterate the shortlist itself.
- **Progressive rendering is not attempted:** placeholders show until the compatibility worker posts its report; per-row on-demand probes are the only incremental path.
- **Default intent:** the panel starts on "fine-tune" (base models) and offers "predict now" (finetuned models with heads) as the second route; the task filter is optional.
