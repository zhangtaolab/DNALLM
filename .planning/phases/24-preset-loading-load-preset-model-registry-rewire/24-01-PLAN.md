<objective>
Rewire exactly one function — `load_preset_model` at `dnallm/models/model.py:1567` — so a lookup name resolves FIRST through the Phase-22 packaged model registry (entry name, then repo id, via `try_resolve`), falls back to the legacy `MODEL_INFO` family table, and otherwise returns 0 unchanged (LOAD-01). A resolved finetuned entry patches `num_labels` / `label_names` / `threshold` into a COPY of the caller's `TaskConfig`, validates `task_type` (never patches it), and logs its `base_model` lineage. The grep-verified dead preset-list flatten branch is replaced, the existing family-name behavior is regression-tested over the ten zhangtaolab-default families, and the intentional 24-name collision delta is pinned and documented.

Purpose: the registry becomes the runtime truth source for preset names — a user passes a registry entry name (e.g. a PlantHelixSeek checkpoint) and gets a correctly-shaped model with no manual config editing; a wrong `num_labels` can no longer build a wrong-shaped head.
Output: rewired `dnallm/models/model.py::load_preset_model` + rewritten/extended `tests/models/test_model.py`. No other file changes; `dnallm/models/registry.py`, `dnallm/models/modeling_auto.py`, `dnallm/configuration/configs.py` are read-only this phase.

Recorded plan-time decisions (from 24-RESEARCH.md Open Questions, resolved here):
- **OQ-1 → STRICT (D-05 smallest interpretation):** the six registry entries carrying `task_type='classification'` (PlantCAD2 family, third-party) are NOT aliased to user 'binary'/'multiclass' — no valid TaskConfig can match them, so loading one by name raises the D-05 ValueError. This is a documented known limitation (all six are outside every zhangtaolab flow); a real-entry test pins the decision. A registry data fix is out of phase scope (261020-kwt discipline: scripted insertion, separate change).
- **OQ-2 → docstring discloses resolution order:** the rewritten docstring states the order (packaged model registry first — entry name then repo id; registry wins when a name is both a registry entry and a family key; family table fallback; 0 on miss) without turning into a migration note and without naming the registry data file literally.
- Assumption carried (research A2): whether ModelScope hosts the canonical-upstream repo ids for the 24 collision names is unknown and out of D-09 scope — the delta is documented (docstring + pinned test) so the behavior change is intentional and discoverable.
</objective>
