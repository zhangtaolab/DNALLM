<objective>
Build `check_config_registry_consistency()` — a read-only, repo-id-keyed comparison of every per-model MCP inference YAML against the Phase-22 registry — and gate CI on it (MCP-01 + MCP-03). New module `dnallm/mcp/consistency.py`: parse each `*_inference_config.yaml` in a config directory with `yaml.safe_load`, key it via `registry.try_resolve(config["model"]["path"])`, compare the four D-04 hard fields (`task_type`, `num_labels`, `label_names` order-sensitively, `threshold`) plus the three soft tiers (`source` derived from `is_lab_model`, `max_length` via `effective_max_length`, `description` informational), collect ALL mismatches as preflight `Finding`s in one pass, and return a frozen `ConsistencyReport` whose `passed` bool is the machine-readable signal (D-12). Every `mcp_server_config*.yaml` gets reference-integrity checking of its `models[*].config_path` entries (D-03). The MCP-03 CI gate is a pytest test under `tests/mcp/` that runs the checker over the committed `dnallm/mcp/configs/` with `strict_registry=True` — running in every CI lane via the existing `testpaths`, zero workflow edits (D-18).

Purpose: config↔registry drift fails the build instead of silently shipping confidently-wrong predictions — a swapped `label_names` order inverts every prediction's meaning without raising an error, and today nothing would catch it.
Output: `dnallm/mcp/consistency.py` + facade re-export + `tests/mcp/test_config_registry_consistency.py`. No other production files change; `dnallm/models/registry.py`, `dnallm/preflight/report.py`, and every committed YAML are read-only this plan.

Recorded plan-time decisions (planner discretion from 26-CONTEXT.md, exercised here):
- **Module location → new `dnallm/mcp/consistency.py`** beside `config_validators.py`: the checker is a scan/report service, not a validator extension; a dedicated module keeps `config_validators.py` as pure Pydantic schemas and gives the CI gate a single importable symbol.
- **Parse route → direct `yaml.safe_load` + dict access, NOT the `InferenceModelConfig` round-trip** (26-PATTERNS.md Analog B): a validators schema change must not be able to break the checker, and the checker must report on malformed configs it can still partially read. Missing `task`/`model` sections → `CONFIG_INVALID`; parse failure → `CONFIG_UNREADABLE`.
- **Severity/tier table (D-12 signal shape):** hard-field mismatch → WARN + strict-fatal; unknown repo / source mismatch / max_length mismatch → WARN, never strict-fatal; description divergence → INFO; unreadable/invalid config + dangling server-config reference → ERROR, fatal in BOTH modes (an unreadable committed file is breakage, not drift — warn-first still means never raising, and the report carries it). STRICT_FATAL set = exactly the four hard-field reason codes.
- **Gate-test location → `tests/mcp/test_config_registry_consistency.py`** (tests mirror package; `testpaths` covers it on every CI lane).
- **Reason codes:** `TASK_TYPE_MISMATCH`, `NUM_LABELS_MISMATCH`, `LABEL_ORDER_MISMATCH`, `THRESHOLD_MISMATCH` (strict-fatal); `MODEL_NOT_IN_REGISTRY` (name reused from `CompatReasonCode`), `SOURCE_MISMATCH`, `MAX_LENGTH_MISMATCH` (WARN, never fatal); `DESCRIPTION_DIVERGED` (INFO); `CONFIG_UNREADABLE`, `CONFIG_INVALID`, `DANGLING_CONFIG_REFERENCE` (ERROR).
</objective>
