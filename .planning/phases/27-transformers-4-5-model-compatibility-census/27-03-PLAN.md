<objective>
D-07 write-back: the census verdicts become permanent registry fields. `RegistryEntry` gains three optional-nullable compat fields (REG-02 enrichment shape), the 49 pretrained rows of `model_info.yaml` gain their values via scripted anchored text insertion, and the REG-03 integrity tests extend in the same change.

Purpose: the registry is the runtime single source of truth (v1.4 milestone spine). Compatibility verdicts live where `tokenizer_type`/`max_length` live, so every consumer (docs generation, CI gate, dispatch lane, future runtime notice) reads one typed loader.

Output: extended registry schema + data + tests (one atomic data commit), `--write-registry` tool mode, artifact↔yaml consistency test.

Decisions implemented: D-01 (49 pretrained entries only - finetuned entries inherit from their bases, carrying no fields), D-05 (the version stamp records what was ACTUALLY tested: transformers 5.17.0 - the 4-side inference lives in the docs layer, never in a both claim), D-07 (registry fields + REG-03 extension; one-way: REG-03 treats registry fields as insertion-only).

Field schema (planner decision within D-07 discretion, following the research Open-Question-3 recommendation of evidence-descriptive vocabulary):
- `tf_compat_status: Literal["verified-tf5", "import-verified-tf5", "shim-required-tf5", "remote-code-broken", "census-blocked"] | None`
  - `verified-tf5` - load + one real forward empirically passed under transformers 5.17.0 (family representatives, native representatives)
  - `import-verified-tf5` - import/arch resolution passed under 5.17.0; load inferred from the family representative (honest sibling label)
  - `shim-required-tf5` - works under 5.17.0 only via the Phase-27 compat rungs; load + forward verified under the shim (D-02a)
  - `remote-code-broken` - structurally unfixable under 5.17.0; `tf_compat_evidence` carries the exact failing import
  - `census-blocked` - unreachable or unresolvable (e.g. cross-repo auto_map); reason in evidence
- `tf_compat_evidence: str | None` - hub@revision stamp plus the failing import (broken entries), the rung name (shim-required), or the family-representative repo (import-verified)
- `tf_compat_tested: str | None` - the transformers version actually tested, `"5.17.0"`

Mapping from the final artifact: `import-fail`+skip → `remote-code-broken`; `import-fail`+fix, recovered, load forward true → `shim-required-tf5`; family rep / singleton with load forward true → `verified-tf5`; import-ok/arch-ok non-rep → `import-verified-tf5`; `census-blocked` → `census-blocked`.
</objective>
