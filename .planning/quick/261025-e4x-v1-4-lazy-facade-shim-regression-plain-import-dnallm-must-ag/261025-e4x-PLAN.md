## Design decision (measured, both candidates probed live on v1.4 tip)

**Rejected — eager module-level `import dnallm.utils.transformers_compat` in the
root init:** measured 2.037s (it pulls torch at module scope, then
transformers.modeling_utils through apply_patches) against the 0.177-0.191s bare
`import dnallm` baseline. It would also turn the pinned Phase 25 contract test
`tests/test_package_facade.py::test_import_preflight_is_torch_free` red: that test
imports `dnallm.preflight`, which runs the root init, and asserts HEAVY is empty.
Phase 25 plan 25-03 records D-01 as human-settled ("the wizard must start textual
immediately", 3.91s -> 0.29s) with reversibility rated "costly". Regressing every
light path (TUI first paint, `dnallm --help`, MCP bootstrap) is not an acceptable
price for the fix.

**Chosen — lazy activation via a stdlib-only meta-path hook armed in the root
init:** feasibility-probed live in the dev venv. Arming costs ~0.0000s and imports
no torch. A finder at `sys.meta_path[0]` watches exactly one name, the root
`"transformers"` package (importing ANY transformers submodule first executes the
root package, so one watch name covers every entry route). On the first
`transformers` import it delegates spec resolution to the remaining meta_path
chain, wraps the loader's exec_module so the real module body always executes
first, and only then imports `dnallm.utils.transformers_compat` — whose module
tail (line 1408) already runs `apply_patches()`, idempotent by its own sentinels.
If `transformers` is already in sys.modules at arm time (the notebook cell order:
transformers imported before dnallm), arm activates immediately instead. The
Phase 25 PEP 562 facade is otherwise untouched: `_LAZY`, `__getattr__`, parity and
ordering contracts all stay as committed.

**Assumption-delta record (advisory checkpoint):** the facade made compat
activation required->optional in effect; this fix does NOT promote eagerness back.
It adds an alongside path — activation contract AND lazy facade both hold, proven
by the paired contract tests (activation red->green, purity stays green).

**Placement note:** the hook module lives at `dnallm/_compat_activation.py`
(package root, beside the `version.py` precedent; leading underscore per the
repo's private-module convention) — NOT under `dnallm/utils/`, because importing
any `dnallm.utils.*` module first executes the utils facade init, measured at
0.173-0.194s (loguru chain), which would visibly double the root light-path cost
the fix is required to preserve.

## Failure mechanics (from run 40140203118, verified live on tip)

main (merge-base f7a7fcb) eagerly imported .models/.datahandling/.finetune/.inference
from the root init — each imports transformers_compat, whose import tail runs
apply_patches(), attaching the vendored v4.49 pruning helpers onto
transformers.pytorch_utils and transformers.modeling_utils. v1.4's root facade
binds only __version__ / load_config / cli eagerly, so a notebook that imports
ONLY the root never activates the shim, and the remote modeling_esm.py of
InstaDeepAI nucleotide-transformer checkpoints fails its
`from transformers.pytorch_utils import find_pruneable_heads_and_indices`.
Live confirmation on v1.4 tip (dev venv, transformers 5.17): bare
`import dnallm` then `import transformers.pytorch_utils` — helper absent, shim
module absent; same for the transformers-before-dnallm order. Notebooks execute
under a dedicated nbclient kernel per notebook (tests/examples/_execution.py), so
the notebook's `import dnallm` is a genuinely fresh root-init run — the hook fires
in that kernel.
