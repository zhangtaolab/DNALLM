<objective>
Per-lane workflow_dispatch selection for the three nightly lanes in ci.yml.

Problem: a manual `workflow_dispatch` today fires ALL three nightly lanes
(coverage-nightly ~4h, example-nightly ~1.5h, test-mamba ~25min+build),
queue-serialized on the single self-hosted dnallm-nightly runner (~6h total).
The Actions REST API cancels runs, not individual jobs (run 40246863966:
POST /actions/jobs/{id}/cancel -> 404), so a misaimed dispatch cannot be
lane-trimmed after the fact.

Change: three `type: boolean` dispatch inputs, all `default: true`
(no-flag dispatch keeps today's behavior), each nightly job's dispatch arm
ANDed with its own flag. Boolean form verified against GitHub docs
(events-that-trigger-workflows): "The `inputs` context preserves Boolean
values as Booleans instead of converting them to strings" — while
`github.event.inputs` is string-typed (the dispatch REST API itself only
takes string key=value pairs, which is why). Job-level `if` therefore reads
`inputs.<flag>`, never `github.event.inputs.<flag> == 'true'`.

config.json; the brief's line numbers had drifted — #3786 discipline):
